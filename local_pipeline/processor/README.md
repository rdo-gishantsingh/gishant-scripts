# rdo_kitsu processor — local stack

Runs the `rdo_kitsu` processor (kafka + listener + consumer) against the **local**
AYON (`:5000`) and **local** Kitsu via the nginx gateway (`:8090`), never prod.

The base compose file stays in the add-on repo
(`~/dev/repos/rdo-ayon-kitsu/services/processor/docker-compose.yml`); everything here is
a local-only overlay on top of it.

| File | Purpose |
|---|---|
| `docker-compose.local.yml` | Overlay: local AYON URL, addon name/version, sync interval, `restart: unless-stopped`. Committed — contains no secrets. |
| `.env.local.example` | Documents every variable. Committed. |
| `.env.local` | Generated by `up-local-stack.sh`, holds the API key. **Gitignored.** |
| `up-local-stack.sh` | Regenerates `.env.local`, validates the merged config, brings the stack up. |

## Order of operations

The processor reads the Kitsu URL and token from AYON add-on settings at startup and
raises if they are unset, so it must come up **last**:

```bash
sudo ~/dev/repos/gishant-scripts/scripts/sync-and-restore-databases.sh   # 1. restore DBs
python -m gishant_scripts.ayon.localize_kitsu_addon --apply              # 2. point addon at local Kitsu
./up-local-stack.sh                                                      # 3. start processor
```

## Secrets

`AYON_API_KEY` is read at runtime from `src/gishant_scripts/ayon/ayon-server/.env` and
written into `.env.local` (mode 0600). No key is ever committed. `up-local-stack.sh`
refuses to start if `AYON_SERVER_URL` does not look local.

## Two things worth knowing

**`AYON_ADDON_VERSION=0.3.3` must exist on the local server.** It matches
`rdo-ayon-kitsu/package.py`, but the restored DB decides which add-on versions are
actually installed. If `0.3.3` is not among them the processor dies at startup with
`Kitsu server URL not set in AYON settings`. Check before starting:

```bash
curl -s -H "x-api-key: $KEY" http://10.1.69.24:5000/api/addons | jq '.addons[]|select(.name=="rdo_kitsu").versions|keys'
```

The base compose still pins the processor **image** to `redefineoriginals/rdo-kitsu-processor:0.3.2`.
That tag is the container build, independent of `AYON_ADDON_VERSION`; it is left alone
here. Add `--build` to `up-local-stack.sh`'s `compose up` if you want the local source built instead.

**`STARTUP_FULL_SYNC` does not exist.** Nothing in the processor reads it —
`rdo_kitsu_processor/config.py` defines no such field, so setting it is a silent no-op.
A full sync is a per-project AYON call that the listener enrols on:

```
POST {AYON}/api/addons/rdo_kitsu/0.3.3/sync/{project_name}   -> dispatches kitsu.sync_request
```

`localize_kitsu_addon.py --full-sync` issues exactly that for each paired project.
